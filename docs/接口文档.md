# 接口文档

## 约定

- 基础路径：`/api`，以 `application.yml` 为准；下列路径已包含该前缀。
- 认证使用请求头 `Authorization: Bearer <JWT>`（拦截器也接受裸 JWT）；“是”表示拦截器要求有效令牌，不代表接口均有角色或资源归属校验。
- `/auth/**` 和 `/roomType/**` 均未经过认证拦截，包含房型写接口；`/external/**` 和 `/operating-expenses/**` 还要求员工类型且角色为 `owner`。
- 常规响应为 `Result`：`code`（业务状态码）、`message`（消息）、`data`（业务数据）、`timestamp`（响应时间戳）；分页 `data` 含 `records`、`total`、`size`、`current`、`pages`。日期一般为 `yyyy-MM-dd`；经营支出时间参数为 `yyyy-MM-dd HH:mm:ss`。
- 列表接口的字段表描述数组元素；分页接口的字段表描述 `records` 的元素。
- 字段“未确认”表示 Controller/DTO 未明确声明校验约束，不代表服务一定接受空值。实体直接作为请求体的接口列出可绑定字段，最终校验和服务端覆盖行为以实现为准。

## 待确认和实现差异

- 房型所有路径均被认证拦截排除，其中新增、更新、删除接口也无需令牌；不应仅根据业务名称推断其权限。
- 员工登录服务直接将输入密码与数据库字段比较；员工密码重置接口将密码设为固定初始值，且 Controller 未单独检查角色；实际部署中的补充权限限制未确认。
- 多个 Controller 直接使用 Entity 接收或返回数据，且未通过 DTO 显式约束所有字段；业务必填项和敏感字段暴露应结合实际调用链进一步核验。
- 小程序订单及第三方订单可在统一列表和日历中只读合并展示，但跨来源预订冲突未联动检查。
- 统一订单查询的 `startDate`、`endDate` 必须同时传入；`platformId=-1` 代表小程序。统计响应的 `total`、`daily`、`platforms`、`anchors`、`rooms` 分组项包含 `name`、`orderCount`、`nights`、`totalAmount`、`platformFee`、`anchorFee`、`netProfit`。
- `/external/statistics` 使用已入住和已退房订单并按住宿日分摊；退款未自动从小程序订单房费中扣除，不能直接视为退款后的实际收款。
- 支付和微信相关真实外部系统行为、运行环境配置及部署版本未通过静态代码确认。
