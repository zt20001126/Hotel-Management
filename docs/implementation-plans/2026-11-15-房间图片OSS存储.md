# 房间图片接入阿里云 OSS 实现方案

日期：2026-11-15　状态：待审阅

## 目标与假设

管理后台上传房间图片到 OSS，保存房型后，小程序和管理后台可以查看图片。沿用现有私有 Bucket 和阻止公共访问设置；本地存储保留为开发环境选项。已有本地图片和外部 URL 继续兼容，不自动迁移。以上是基于当前讨论的建议方案，实际实施前需确认图片访问域名及新凭证配置。

Bucket `qianxunminsu` 只读测试返回的地域为上海，配置使用 `https://oss-cn-shanghai.aliyuncs.com`。已在聊天中暴露的密钥应停用并轮换；不将密钥、签名 URL 写入仓库或日志。

## 现状

- `backend/src/main/java/com/homestay/module/common/controller/FileController.java` 的单文件和批量接口直接写入本地目录，返回 `url`、`name`。
- `backend/src/main/java/com/homestay/module/room/controller/RoomTypeController.java` 提供房型分页、可用列表、搜索、详情、新增和更新接口，直接返回 `RoomType`。
- `backend/sql/homestay_db.sql` 中 `room_type.images` 为 JSON 数组字符串；`frontend/admin/src/views/room/RoomType.vue` 把上传返回的 URL 放入数组后原样保存。
- 小程序 `pages/rooms`、`pages/room-detail`、`pages/booking`、`pages/order-modify` 消费房型图片数组。现有本地图片通过 `/uploads/**` 暴露，外链图片亦可保存。

## 设计与数据流

管理后台 → 现有上传接口 → 文件存储服务 → OSS；上传结果返回稳定的对象标识和临时预览 URL。管理后台保存对象标识，预览使用签名 URL。房型读取时后端将 OSS 对象标识转换为临时签名 URL，并保留稳定标识供管理后台编辑提交；数据库只存稳定标识，不存签名 URL。历史 `/uploads/` 路径及外部 URL 原样处理。

建议使用明确前缀 `oss://qianxunminsu/rooms/...` 区分对象标识与历史 URL。仅接受配置的 Bucket 和受控前缀，避免为任意对象签名。签名地址设定可配置有效期；签名过期后通过重新获取房型数据刷新。图片域名需支持 HTTPS、私有对象签名及小程序加载；OSS 默认域名可能触发下载响应，正式运行前验证并按需绑定自定义域名及配置小程序合法域名。图片展示可被访问者转发，有效期内签名地址持有者均可访问。

房型读取建议引入响应 DTO，保留 `images` 为可显示 URL 的 JSON 字符串以兼容小程序，并新增 `imageRefs` 为稳定标识数组供管理后台保存；不要在实体上改写数据库字段后再复用实体进行保存。后台上传回包添加 `objectRef`，`url` 保持预览含义；编辑时从 `imageRefs` 构造保存列表，同时用 `images` 对应展示。现有纯外链和本地路径在两个数组中一致。其他使用房型数据的页面和接口应在实施时逐一搜索核对。

## API 与数据库影响

| 接口 | 变更与兼容性 |
|---|---|
| `POST /api/file/upload` | 保留 `url`、`name`；OSS 模式新增 `objectRef`，`url` 为临时预览地址。 |
| `POST /api/file/upload/batch` | 每项同上；单项失败的处理沿用现有行为并明确提示。 |
| `POST /api/file/add-url` | 不变，外部 URL 原样作为稳定引用。 |
| `GET /api/roomType/page`、`/available`、`/search`、`/{id}` | `images` 仍为 JSON 字符串，返回可展示地址；新增 `imageRefs`，对应稳定引用。 |
| `POST /api/roomType`、`PUT /api/roomType` | 路径及 `images` 字段不变，管理后台写入稳定引用；服务端校验禁止保存自身签名 URL。 |
| `DELETE /api/roomType/{id}` | 不变，不自动删除 OSS 对象。 |

数据库 `room_type.images` 字段和表结构不变，存储 JSON 字符串数组；新 OSS 图片保存稳定标识。旧数据不需要迁移，部署期间保留本地上传卷和静态资源映射。上线前验证字段长度和混合数据可正常解析。回滚前先评估已保存的 OSS 标识：旧版本不能直接显示它们，须先转换为可访问地址或回迁图片，再回滚应用。

## 实施顺序与验收

1. **配置与存储服务**：添加 SDK、配置、存储接口和本地/OSS 实现。验收：local 模式不需要 OSS 凭证仍可上传；OSS 模式上传后返回稳定对象标识和可访问的短期地址；配置缺失或上传失败时明确报错，不泄漏凭证。
2. **接入现有上传接口**：替换控制器内部磁盘写入。验收：单文件和批量接口保持原字段；非图片及超限文件被拒绝；未授权调用不能上传。
3. **房型读取与管理后台**：增加引用转换、DTO 和前端编辑逻辑。验收：数据库只保存稳定标识；刷新、重新编辑、排序、删除图片并保存后不丢失引用；签名过期后重新读取可再次显示；历史本地与外链图片仍可显示。
4. **部署与小程序验证**：将环境变量传入容器，配置 HTTPS 图片域名。验收：管理后台上传和预览成功，小程序房型列表、详情、预订及修改订单页可展示图片；私有对象无签名访问被拒绝，签名到期后无法访问。
5. **验证与回滚**：增加针对引用解析、外链兼容、签名过期及接口契约的测试；在测试 Bucket 手动完成上传、读取及错误权限检查。验收：相关测试通过，部署说明列明密钥轮换、对象权限、旧图片保留及回滚步骤。

## 六个房间素材的一次性初始化

本机检查 `E:\qianxun\素材\lr`，六个目录共 61 张 JPG、约 138.95 MiB：`101 轻奢` 10 张、`102 浅溪` 11 张、`103 云岸` 9 张、`201 榻榻米` 7 张、`202 清汀` 10 张、`203 木荷` 14 张。另有 `户外` 文件夹及根目录图片，不包含在本次导入中。现有 SQL 初始化数据对应的是六种房型，而非房号：建议分别映射到“枕澜·智能轻奢大床房”“浅溪·智能双床房”“云岸·智能双床房”“冷江·榻榻米大床房”“清汀·智能双床房”“木荷·智能浴缸大床房”；实际数据库 ID 和名称在执行前核验，禁止直接假定 SQL 初始 ID 与线上一致。

导入工具为独立的一次性命令，默认 dry-run，启动应用时不自动执行；参数指定素材路径、明确映射文件和执行模式。dry-run 输出每个目录、目标房型 ID/名称、照片数、排序和预计替换的旧图片，检查缺失/重复房型、空目录、图片格式、大小及数据库可访问性。按文件名排序，第一张作为封面；具体封面需由使用者确认。

明确执行后，逐张上传至 `rooms/<room-type-id>/<内容哈希>.<扩展名>`，由文件存储模块复用 OSS 客户端，数据库中写 `oss://...` 稳定引用。哈希键使同样内容重复执行不会无意义地产生重复对象；实现时核验内容并记录成功/失败结果。逐房型在全部图片上传成功后，用数据库事务替换该房型的 `images`；上传失败则保留该房型原有图片并记录失败，可重复执行。导入前备份原 `images` 引用，输出可用于回滚的映射文件；已成功上传但未关联的对象需记录，不能贸然删除共享对象。导入为追加还是替换属于用户需确认的业务选择，默认方案建议在明确确认后替换示例图片。

导入脚本应支持大于现有后台上传限制的本地原图，但上传前建议在临时输出目录生成适合展示的压缩副本，保留原图不变；目标尺寸和质量在实际观察图片效果后确定。OSS 私有对象仍由后端按现有方案生成签名 URL。验收：dry-run 无任何 OSS/数据库写入；执行结果可核对 61 张及各房型数量，重复执行不产生重复引用；任意房型中途失败不覆盖该房型旧数据；管理后台及小程序可显示导入图片。上述数据量为本机检查结果，运行前重新扫描。
