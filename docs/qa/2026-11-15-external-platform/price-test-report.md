# 第三方平台订单金额专项测试报告

日期：2026-11-15。测试目标是手动输入的成交额、平台手续费、主播手续费，以及按住宿日期分摊后的营业额和净利润。测试使用隔离的临时 MySQL、模拟平台数据与无头浏览器，不访问或修改实际经营数据库，也不连接真实第三方平台。

## 统计口径

- 订单净利润 = 成交金额 − 平台手续费 − 主播手续费，可为负数；不扣除其他经营支出。
- 按计划住宿夜分摊成交额及两项费用，每项独立计算，余分从最早住宿夜依次分配。
- 已入住和已退房订单进入统计，已预订及已取消订单不进入经营收入统计。
- 月、日期和筛选维度的订单数在查询范围内对订单去重；跨月各月订单数不可直接相加替代跨月去重。

## 测试结果

| 场景 | 测试方式和结果 |
|---|---|
| 1 至 366 晚 | 对 9 个边界金额逐一检查每晚分配及整单总额守恒，全部通过 |
| 随机金额和晚数 | 固定随机种子生成 5,000 组，逐晚检查分配顺序、各晚金额与金额守恒，全部通过 |
| 金额边界 | 0 元、0.01 元、不能整分摊的金额和 `DECIMAL(12,2)` 最大单笔金额 9,999,999,999.99 元，通过 |
| 输入校验 | 负手续费、超过两位小数、超出单笔金额字段范围、无主播但主播费非零，被拒绝 |
| 跨年 | 三晚订单跨 12 月和 1 月，按实际查询日期取分摊值；全年查询订单数去重，通过 |
| 闰年 | 2048 年 2 月 29 日跨月分摊，最大单笔金额与 0.01 元手续费的月份归属正确 |
| 多订单与维度 | 多平台、主播、房间分别筛选，订单数、间夜、成交额、手续费及净利润与手工计算一致 |
| 零金额与负利润 | 0.01 元成交、0.03 元手续费的订单净利润为 −0.02 元，按天和汇总结果一致 |
| 状态 | 已入住、已退房计入；已预订、已取消不计入；空期间返回零，通过 |
| 页面输入计算 | 无头 Chrome 使用模拟接口，录入 100.01 − 0.01 显示 100.00；录入 0.01 − 0.02 显示 −0.01，通过 |

### 手工核对样例

三笔订单合并统计 2050 年 1 月：

| 统计项 | 预期及实际结果 |
|---|---:|
| 订单数 | 3 |
| 间夜 | 4 |
| 营业额 | 103.34 元 |
| 平台手续费 | 3.86 元 |
| 主播手续费 | 5.91 元 |
| 净利润 | 93.57 元 |

跨年汇总重新去重后为 3 单、6 晚，营业额 110.02 元、平台手续费 4.54 元、主播手续费 7.25 元、净利润 98.23 元。上述结果由 MySQL 集成测试断言。

## 执行情况

- 后端 `mvn test`：26 个测试方法，25 通过、0 失败、1 跳过；跳过项是已有经营支出集成测试。本次启用了第三方平台 MySQL 集成测试。
- 分摊测试共执行 8,294 组确定性金额／晚数组合，每组验证所有房晚和总额。
- 管理端 `node test/external-calendar-smoke.cjs`：通过，包括表单金额与负利润显示；接口使用模拟数据。
- 测试未发现上述范围内的金额计算错误，本轮未修改业务计算代码。

## 覆盖限制

- 并未穷举所有可能金额和订单组合；随机测试和边界值测试不能证明不存在任何错误。
- 未在真实业务数据库中插入测试订单，也未验证第三方平台实际结算、退款、手续费变动或平台对账文件；系统按手工输入的费用统计。
- 未进行超大量订单、超出 JavaScript 安全整数精度的极大汇总金额的压力和前端精度测试。
- 浏览器测试使用模拟接口，未覆盖完整的浏览器到真实后端再到数据库的全部录单流程。当前阶段不合并小程序金额。
