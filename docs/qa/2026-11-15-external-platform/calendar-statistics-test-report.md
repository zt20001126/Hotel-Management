# 第三方平台房态日历和经营统计测试报告

日期：2026-11-15。测试使用独立临时 MySQL 和无头 Chrome 模拟接口，没有访问或修改实际经营数据。

## 发现并修复

在经营统计页面快速连续查询时，如果较早的请求比后发请求晚返回，旧结果会覆盖最新查询结果。无头浏览器使用受控的倒序响应复现：第二次结果为 222，第一次旧结果为 111，修复前最终错误显示 111。

页面现通过请求序号只接受最近一次查询的结果；自动测试验证旧请求晚返回后仍显示 222。此问题是单人快速操作也可能遇到的页面查询问题，与多人编辑订单无关。

## 覆盖场景

| 场景 | 结果 |
|---|---|
| 日、周、月视图 | 无头浏览器检查日期列数和视图切换，通过 |
| 日历日期边界 | MySQL 验证入住日计入、退房日不计入，跨年订单正确显示，通过 |
| 日历订单状态 | 已预订、已入住、已退房显示；已取消不显示，通过 |
| 平台筛选 | 日期和平台组合查询仅返回匹配订单，通过 |
| 历史房间 | 房间逻辑删除后，数据库日历接口仍返回历史房间名称；浏览器模拟历史房间和详情显示，通过 |
| 日历接口异常 | 浏览器验证请求失败后不继续显示旧房态，通过 |
| 多维筛选 | 平台、主播、房间联合筛选，以及无匹配订单结果，通过 |
| 统计日期 | 单日、跨月、闰日、无效日期范围，结合已有跨年和余分测试，通过 |
| 统计金额和状态 | 营业额、手续费、净利润、订单数和间夜，以及预订/取消排除，结合金额专项测试通过 |
| 统计请求乱序 | 浏览器模拟两次查询响应倒序，修复后保留最新结果，通过 |

## 执行结果

- Maven：36 项测试方法，35 通过、0 失败、1 跳过；跳过项为既有经营支出集成测试。启用了第三方平台 MySQL 集成测试。
- 管理后台 `node test/external-calendar-smoke.cjs`：通过，API 由本机模拟服务提供。
- 管理后台 Vite 生产构建：通过；有项目现有的 Sass 弃用和产物体积提示。

## 范围和限制

- 房态仅覆盖第三方平台订单，不能判断小程序是否占用房间，也不能阻止跨渠道超卖。
- 浏览器测试使用模拟接口；未进行浏览器连接真实后端和真实数据的完整操作验收。
- 未进行真实小程序支付端到端回归、生产数据库升级验证或大数据量压力测试。
- 同一订单的旧表单覆盖风险按用户确认的单管理员使用场景暂不处理；本次统计查询乱序问题已独立修复。
