# 第三方平台订单生命周期及房态测试报告

日期：2026-11-15。使用单独启动的临时 MySQL 数据库，未连接或修改实际经营数据库。

## 测试范围和结果

| 场景 | 结果 |
|---|---|
| 新增订单 | 合法订单保存后可查询，日期无效、退房不晚于入住、超过 366 晚、无主播却填写主播费均被拒绝 |
| 房态区间 | 验证完全相同、包含、被包含、前后部分重叠均拒绝；前一单退房日等于后一单入住日时允许 |
| 平台订单号 | 同平台重复拒绝，不同平台相同订单号允许；空白统一为空，可录入多个无平台号订单 |
| 修改订单 | 可修改房间、日期、金额并重新计算净利润；冲突或平台订单号重复时拒绝，原房间、日期和金额保持不变 |
| 修改后的房态 | 改房成功后原日期释放，新房间对应日期占用；HTTP 接口接收页面提交的额外显示字段并正确保存 |
| 取消订单 | 已预订订单取消后不再显示在房态中，原订单仍可查；同房同日期可重新预订，重复取消拒绝 |
| 状态限制 | 未入住不能直接退房；入住后不能取消或编辑；已退房订单仍占用其计划住宿日期 |
| 停用平台 | 停用平台不能用于新订单；已有订单可保留原平台并修改 |
| 并发新增 | 两个请求同时预订同一房间和日期，只有一笔成功 |
| 并发改房 | 两笔不同订单同时改到同一目标房间、相同日期，只有一笔成功，另一笔收到房态冲突错误 |
| 小程序隔离 | 既有隔离测试检查第三方新增、取消前后小程序订单表记录数不变；现有订单和支付单元测试通过 |

本轮最终执行 `mvn test`，启用第三方 MySQL 集成测试：**34 项测试方法，33 通过、0 失败、1 跳过**。跳过项是既有经营支出集成测试；本次未启用它。通过的测试包含下述对旧数据覆盖行为的复现，因此测试通过不代表该风险已修复。

## 已复现的问题：旧表单覆盖其他人的修改

两个编辑页面同时读取相同的预订订单。第一个页面将平台手续费从 10 元改为 15 元并保存；第二个页面使用仍含 10 元手续费的旧数据，仅修改备注后保存。实际结果：手续费被写回 10 元，且没有冲突提示。隔离数据库测试已复现。

原因是当前更新只校验订单 ID 和状态，没有判断提交的数据是否基于最新版本。它与不同订单争抢同一房间的并发冲突检查是两回事。本轮没有修改业务代码；要消除该风险，需要设计并实施订单版本校验，以及相应的接口和页面冲突提示。

## 限制及待验证事项

- 房态只检查第三方平台订单，按已确认的第一阶段范围，不检查小程序或外部平台实时订单，无法防止跨渠道超卖。
- 本次并发检查覆盖两笔订单争抢同一目标房间；并发测试不能覆盖所有可能的请求时序或负载。
- 相同订单的旧表单覆盖问题已复现但尚未修复，详见上文；在多页面或多人同时编辑时应避免使用旧表单保存。
- HTTP 接口与隔离数据库已验证，但本轮未进行浏览器连接真实后端的完整新增、修改、取消操作，也未进行小程序真实支付端到端测试。
- 当前测试数据库与实际经营数据库隔离；未使用现有业务订单作为测试数据。
