# 小程序订单接入测试用例

| 用例ID | 测试类型 | 测试场景 | 输入 | 预期输出 | 是否通过 |
|---|---|---|---|---|---|
| ST-01 | 状态 | 待支付 | awaiting_payment，支付 0 | 日历待支付，不统计 | 通过 |
| ST-02 | 状态 | 部分支付 | pending，支付 50/100 | 日历待支付，不统计 | 通过 |
| ST-03 | 状态 | 已支付 | pending 或 confirmed，支付 100/100 | 日历已预订，不统计 | 通过 |
| ST-04 | 状态 | 已入住／已退房 | checked_in、checked_out | 日历显示，报表计入 | 通过 |
| ST-05 | 状态 | 取消订单 | cancelled | 日历和报表排除 | 通过 |
| RM-01 | 房间 | 房型对应一间房 | room_id 为空且唯一映射 | 日历显示该房间 | 通过 |
| RM-02 | 房间 | 房型对应多间房或无房 | room_id 为空 | 显示待确认房间，不任意指定 | 通过 |
| RM-03 | 房间 | 已分房或房间逻辑删除 | 实际 room_id 与推导房不同 | 优先实际房间，历史名称可查 | 通过 |
| AM-01 | 金额 | 跨月、闰年、余分 | 小程序 100.01 元加第三方 20.01 元 | 各日及维度金额、手续费、净利润和间夜符合分摊规则 | 通过 |
| AM-02 | 金额 | 入住后退款 | 模拟退款 1 元 | 合并报表仍按原房费统计；用户确认暂时保持该口径 | 通过（现行口径） |
| DD-01 | 去重 | 不同来源订单数字 ID 相同 | 小程序 ID 与第三方 ID 相同 | 分别计数，不互相覆盖 | 通过 |
| DD-02 | 来源隔离 | 第三方来源筛选 | 选小程序或第三方 | 只统计选择的来源 | 通过 |
| DD-03 | 重复请求 | 重复查询房态和统计 | 同一订单重复查询 | 不创建第三方订单，不变更原订单及支付记录 | 通过 |
| API-01 | 原有流程 | 下单、模拟支付、确认、入住、退房 | 调用现有小程序相关接口 | 原流程成功，入住前后合并结果按状态变化 | 通过 |
| API-02 | 权限 | 未登录、宾客、前台 | 访问合并日历和报表 | 返回未登录或禁止访问 | 通过 |
| API-03 | 空值／负面 | 查询缺少日期、错误日期和 JSON | 不合法请求 | 返回业务错误，不执行服务 | 通过（现有接口测试） |
| UI-01 | 浏览器 | 同房同日多来源及小程序筛选 | 模拟接口 | 两笔显示，小程序详情可查看，筛选请求包含小程序来源 | 通过（模拟接口） |
| REAL-01 | 端到端 | 微信真实支付和真实小程序客户端 | 真实支付环境 | 用户支付与实际页面同步 | 未执行 |
