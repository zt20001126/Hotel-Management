# 小程序订单接入房态与统计测试计划

## Feature scope

验证小程序订单与手工第三方订单在管理员房态、统计中的只读合并，以及既有小程序订单流程的兼容性。历史上两类订单未重复手工录入，此事实由用户确认。

## Module breakdown

- 小程序订单和模拟支付、确认、入住、退房原有接口。
- 第三方模块的订单只读投影、房间映射、日历和统计接口。
- 管理后台日历、订单详情和统计来源筛选。

## Test objectives

检查状态、金额、房间和订单来源；同一笔小程序订单读取一次、两类不同订单的数值 ID 相同也不能误去重；读合并结果不写入或改变原订单、支付记录或第三方订单。

## Test strategy

- **Unit Test**：分摊余数、金额守恒和既有订单支付单元测试。
- **API Test**：MockMvc 验证 `/order` 下单、确认、入住、退房及 `/external/calendar`、`/external/statistics`；额外验证未登录、宾客及非经营者访问限制。
- **Integration Test**：隔离 MySQL 中执行真实服务、Mapper 与 SQL；比较合并查询前后小程序订单、支付记录及原有统计响应。
- **Boundary Test**：跨月、闰日、相同数字 ID、无房和多房型映射；对每笔金额按实际日期核算。
- **Negative Test**：取消和逻辑删除不参与查询；不合法输入、无权限及不满足付款状态的订单不误显示已预订。
- **Idempotency Test**：重复只读查询不增加第三方订单、不更改小程序订单或支付记录；现有第三方重复下单防重测试继续运行。
- **Browser Test**：无头 Chrome 与本机模拟 API 测试同房多来源展示、来源筛选和只读详情；不声称连接真实后端。

测试库和本机浏览器均为临时隔离环境；不执行真实微信支付或修改用户业务数据库。
