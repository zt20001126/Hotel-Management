# 小程序接入房态与统计测试报告

日期：2026-11-15。测试使用临时 MySQL、模拟支付及本机无头 Chrome；未修改实际业务数据库。

## 测试结果

- Maven 最终共 44 项测试方法：43 通过、0 失败、1 跳过。跳过的是既有经营支出集成测试；小程序和第三方订单集成测试已启用。
- 管理后台生产构建通过；无头浏览器冒烟测试通过，使用模拟接口而非真实后端。
- 新增 MockMvc + 隔离 MySQL 测试，运行现有小程序下单、模拟支付、确认、入住和退房，并验证第三方日历与报表状态随之变化。重复读取合并视图前后，小程序订单字段、支付记录数量、第三方订单数量和原有小程序订单统计响应保持一致。
- 补充待支付、部分支付、已支付、入住、退房、取消、房型无房或多房、已分配及逻辑删除房间、跨闰月分摊、多来源筛选和相同数字 ID 测试。
- 用户确认：历史上没有将小程序订单手工录入第三方订单。两种来源按各自订单标识计数，数字 ID 相同不会错误合并。

## 退款口径

测试验证：入住后退款会减少小程序订单的已付金额，但合并经营报表仍以原订单房费作为营业额，退款不自动扣除。用户表示暂不确定最终规则，先保留现状。当前报表数字因此不能等同于退款后的实际收款。

## 风险和上线判断

**待验收，不能仅依据本报告确认可上线。**浏览器测试使用模拟接口；小程序接口链路使用项目现有的模拟支付，不等于微信真实支付和真实小程序客户端端到端验收。合并日历尚未阻止小程序与第三方平台之间的房间冲突；若未来人工重复录入同一实际订单，两张表之间也没有自动识别机制。当前历史数据未重复由用户确认。

房型与房间并非永久绑定：未分房小程序订单按当前唯一房型映射显示，若对应关系改变，历史未分房订单的显示可能变化；不唯一时显示待确认房间。未进行生产规模压力测试。
